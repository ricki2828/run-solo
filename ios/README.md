# Run Supreme iOS project

Generated by `flutter create --platforms=ios .` (Flutter 3.47.5) on the Linux host and committed as is, then edited for I0 (iOS plan `~/ai/plans/run-supreme-ios-plan.md` §3, §5.1, §6). There is no Mac: everything is built on GitHub's macOS runners by `.github/workflows/ios.yml` (manual runs and `v*` tags only).

## Rules

- **Plugins come through CocoaPods only.** `pubspec.yaml` sets `enable-swift-package-manager: false` because `google_maps_flutter_ios` ships no `Package.swift`; leaving SPM on would mix both in one project. `Podfile.lock` is not committed yet: the first green verify run uploads it in `ios-verify-logs`.
- **Extra targets** (Live Activity extension, Watch app) are added by `tools/add_targets.rb` (Ruby `xcodeproj`, run in CI before `pod install`), never by hand-editing the pbxproj. It also checks the Runner settings above. One owner of `project.pbxproj` and `add_targets.rb` at a time.
- **App icon**: regenerate with `assets/brand/build_brand.py`; do not hand-edit.
- **CI digest**: every job writes `ios/tools/error_digest.py` output (about 30 lines) to the job summary and the `ios-verify-digest` artifact. Read that first; full logs are in `ios-verify-logs`.
- **Release build path (T4)**: `flutter build ios --release --config-only`, then `xcodebuild archive` and `xcodebuild -exportArchive -allowProvisioningUpdates` with the App Store Connect API key and `destination: upload`. `flutter build ipa` cannot pass the API key flags.

## Known gaps for P1

- The Pigeon contract only has Kotlin hosts. The app builds on iOS, but every platform call throws a channel error at runtime until P1 adds the Swift host stubs.
- Google Maps on iOS needs `GMSServices.provideAPIKey` in `AppDelegate` before a map is shown, or the plugin aborts. P1 or P7 wires it (secret `RUN_SOLO_MAPS_API_KEY_IOS`).
